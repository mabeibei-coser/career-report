sessionStorage 详解 — 数据的临时储物柜

sessionStorage 是浏览器内置的临时储物柜。这个应用用它来在不同页面之间传递数据，而不需要后端数据库。

1

临时性

关闭标签页数据就没了，不像数据库会永久保存。就像超市的临时寄存柜 — 你走了，柜子就清空了。

2

隔离性

每个标签页的数据互不影响。你在 A 标签页填的表单，B 标签页看不到。就像每个人有自己独立的柜子。

3

隐私性

数据只在你的浏览器里，不会发到服务器存储。你的职业信息不会被留在任何人的服务器上。

设计决策

选择 sessionStorage 而不是数据库，是一个有意的设计决策。对于这种一次性使用的工具，不需要永久保存数据，反而保护了用户隐私。

模块 4

AI 的幕后工作

API 路由就像一位"翻译官" — 把用户的日常对话翻译成 AI 能理解的结构化指令，再把 AI 的回复翻译成用户能看懂的内容。

API 路由 — 前端和 AI 之间的翻译官

你在访谈页打字回答问题时，你的文字其实经历了一段旅程：从浏览器 → 服务器 → AI 模型 → 服务器 → 浏览器。API 路由就是这个旅程的中转站。

1

用户输入回答

用户在访谈页的输入框里打字，写下对问题的回答。

2

浏览器发送请求

浏览器把回答打包成一个 POST 请求，发送到 /api/interview 这个地址。

3

服务器构建消息

服务器收到请求后，把系统提示词、用户背景和对话历史组装好，调用 MiniMax API。

4

AI 返回回复

MiniMax 分析所有信息后，生成下一个访谈问题返回给服务器。

5

清理并返回

服务器清理 AI 回复中的多余标签，把干净的问题返回给浏览器显示。

整个过程就像外交场合的同声传译 — 翻译官（API 路由）在两方之间来回沟通，确保双方都能理解对方的意思。

系统提示词 — 给 AI 的剧本

系统提示词就像导演在开拍前给演员的剧本 — 告诉 AI 它是谁、要做什么、怎么做。写得好，AI 表现就好；写得差，AI 就会跑偏。

const systemPrompt = `你是一位资深职业咨询顾问。
你的任务是通过访谈了解用户的职业情况。
请围绕以下主题提问：
1. 日常工作内容和职责
2. 核心能力和技能水平
3. 工作中的挑战和痛点
4. 职业期望和发展方向
5. 行业趋势的看法

每次只问一个问题，语气专业友好。

第 1 行 告诉 AI 它扮演什么角色 — 一位资深职业咨询顾问
第 2 行 明确任务：通过访谈了解用户
第 3-8 行 给出 5 个提问方向，确保全面覆盖
第 10 行 设定行为规范：一次一个问题，语气友好

系统提示词是 AI 应用最核心的部分之一。它就像给演员的剧本 — 写得好，AI 表现就好；写得差，AI 就会跑偏。这就是为什么"提示词工程"是一个重要技能。

报告生成 — JSON 的魔法

访谈结束后，另一个 API 路由 /api/report 负责生成报告。它要求 AI 把分析结果以 JSON 格式返回 — 这样前端才能用图表展示。

meta 报告元信息（标题、日期）
summary 一段话的定位总结
jobOverview 职责分布（3-5 项，权重加起来 = 100）
competencyProfile 能力画像（5 个维度，雷达图数据）
developmentPath 发展路径（向上/横向/短期/中期建议）
supplementary 薪资范围（低/中/高）+ 对标岗位

但 AI 返回的文本不一定完全"干净"，有时候会多出代码块标记。所以需要一段清理代码：

let content = response.choices[0]
  .message.content || "";
content = content
  .replace(/```json\n?/g, "")
  .replace(/```\n?/g, "");
const reportBody = JSON.parse(content);
第 1-2 行 从 AI 的回复中取出内容
第 3-5 行 有时 AI 会用代码块标记包裹 JSON，需要去掉这些标记
第 6 行 清理干净后，把文本转成程序能理解的结构化数据

AI 的输出并不总是完美的 — 它可能多加标记、格式不对、甚至返回无效的 JSON。所以"清理和修复 AI 输出"是 AI 应用开发中的常见工作。

加载页的精妙设计 — 并行操作

加载页是整个应用最巧妙的设计之一：它同时运行动画和 API 调用，用视觉效果掩盖等待时间。

1

开始

同时启动两个任务 — 就像左手画圆、右手画方，两件事同时进行。

2

任务 A（前台）

播放 8 步动画，总共约 38 秒。用户看到的是精心设计的进度展示。

3

任务 B（后台）

调用 AI 生成报告，时间不确定。用户看不到这个过程。

4

等待

两个任务都完成后才跳转到报告页 — 缺一不可。

5

保险机制

如果动画放完了 API 还没好，显示"正在等待..." — 不让用户干等着不知道发生了什么。

并行操作是软件工程中非常重要的概念。就像厨师可以在等水烧开的时候切菜一样，程序也可以同时做多件事。这里用动画掩盖了等待时间，让用户感觉一切都在有序进行。

数据可视化 — Recharts 图表

报告页里有两种图表，它们让枯燥的数据变成直观的视觉呈现。这两种图表都来自 Recharts 库。

🕸️

RadarChart（雷达图）

展示 5 个能力维度的得分，像蜘蛛网一样。每个角代表一个维度，线条围出的面积越大，综合能力越强。

🥧

PieChart（饼图）

展示职责分布的权重，每块大小代表占比。一眼就能看出哪部分最重要。

第 5-7 行 画数据区域，蓝色填充，30% 透明度

A：因为 API 调用很快不需要等
B：为了节省服务器资源
C：为了用动画掩盖等待时间，提升用户体验

A：安装一个新的图表库
B：用 Recharts 的 BarChart 组件，项目已经有这个库了
